# Slice B, state 3: Individual Question Review. Reading key

**Proposal, for approval with Results (decision 25).** Desktop only, at 1440
and 1280×900. No new feedback architecture: the question, the answer and the
result are the frozen marked states the sitting already draws
(`tmQuestionHTML` and `tmResultHTML` in app.js), set in a review shell that can
only move. The CSS is the app's own: the generator reads `index.html` and keeps
the rules whose classes are on the page, so these pages cannot drift from the
app. Generated by `06-review.build.mjs` from `06-review.fixture.json`.

Each page reviews the attempt a Results page shows, closed exactly as that page
closes it, so a Results cell and the page it opens read one attempt. What a page
says about its question is `ATT.reviewAt`, which returns the Results item for
that key. The marker's feedback is the frozen states' own reviews, run through
the shipped `finalize()` and stored as the app stores it (`kind: "llm"`, `fb`).

## The shell

- **Top bar.** `← Results` returns to the Results page the student came from.
  The paper and section, a neutral *Completed 2 Oct · read only*, the
  **Questions** button, and *Your mark 28/90* (*Nothing marked* when nothing
  was) in place of the sitting's progress bar and *Practice · marked as you go*.
- **Footer.** *← Previous · 11(d)*, *Item 15 of 20 · Section II*, *Next · 12(b)
  →*, through the attempt in paper order (the attempt's own sequence, so a
  practice session runs through its own questions). On the last item Next
  becomes *Back to Results*; on the first, Previous is disabled. There is no
  Flag button: flags are part of the closed attempt and are shown, not changed.
- **Questions navigator.** The sitting's navigator, with Results' words: each
  section's mark (or *nothing marked*), each parent's subtotal, the legend
  *marked · not marked · not answered · flagged · current*, and *Back to
  Results* where the sitting has *Review & submit*. A chip opens that question.
- **Entry.** A Results cell opens that exact item; *Review each question* starts
  at the first answerable (`ATT.reviewAt(a, exams, null)`).

## Where a question stands

Beside the question number, in Results' edges: a light edge for a mark
(**3 / 5**), a solid dark edge for *Not marked · 3 marks*, a dashed edge for
*Not answered · 5 marks* or *Not chosen · 20 marks*. *Changed after marking* is
a second tag that jumps to the later text, and *⚑ Flagged* is shown when it
was. The parent's part chips are the sitting's, so *2 of 4 parts marked* and the
current part read as they did while answering.

## The four states asked for

1. **Marked short answer.** The authored question and source, *Your submitted
   answer* in the frozen read-only box, the result (*Most of it · Marks 3 of
   5*) and *Marked against Business Studies criteria* with the marker's
   summary. Exactly the marked state, with *Try again* and *What would make this
   stronger* removed.
2. **Marked extended response.** The frozen state 12: the collapsed *Your
   submitted response · 176 words*, the result, the summary, *How this was
   marked* with the four criteria in the course's order, and *What the marker
   noticed*, each observation anchored to the student's own sentence or *Across
   your response*. No action.
3. **Submitted, not marked.** The response stays visible (*Your submitted
   answer, not marked*). *Not marked · Marks None*, then *Reason at the time:
   The marker could not be reached.* (`ATT.causeOf`, decision 25) and *This
   attempt is closed, so it stays not marked. Nothing was recorded against your
   answer, and its 3 marks still count in the 90.* No *Try marking again*, no
   advice that was only true while the attempt was open.
4. **Changed after marking.** The box is labelled *The version that was marked*
   and holds exactly the graded snapshot; its mark and feedback sit directly
   under it. The later edit is below the feedback in its own section, *Changed
   after marking, never submitted*: *You changed this answer after it was marked
   and did not submit the change before the attempt closed. The change was
   never marked. The mark above is for the version that was marked, not for
   this text.* The mark never sits next to the later text, and the build checks
   the order.

## The other two

- **Not answered.** The question, *Not answered · Marks None* in a dashed box,
  and *Nothing was submitted for marking for this question, so it earned
  nothing. Its 5 marks still count in the 90.* No feedback. A draft that was
  never submitted is behind *Show what you wrote*, with *You wrote this but did
  not submit it before the attempt closed, so it was not marked.* It is never
  called an answer.
- **Unchosen either/or.** *Neither Question 15 nor Question 16 was chosen. The
  section counted as one question and earned nothing. Its 20 marks still count
  in the 90.* The section's own instructions, quoted, and both questions as the
  paper sets them, as plain text, not buttons: nothing suggests either was
  attempted.

## Not on the page

Editing, *Try again*, *Try marking again*, a second opinion, rewriting,
*Submit for marking*, *Check answer*, flagging, *Choose the other question*,
anything that changes the total, *yet*, *so far*, and the open attempt's
*Saved. You can leave and come back*. The build fails if any appears, if any
textarea is editable, if an item with no mark shows a number or marker
feedback, or if Previous, Next or `← Results` go anywhere but the attempt's
neighbours and the Results page.

## Contract added for this page

`ATT.reviewAt(attempt, exams, key)`: the Results item for the key (status,
mark, cause, flag), the stored result, and three texts kept apart: `answer`
(the version the result was given for), `later` (changed after it, never
submitted) and `unsent` (written for a question nothing was submitted for);
with the neighbours and the position. A null key is the first answerable.
Tested in `tests/t38.mjs`; two mutations prove the tests notice a draft shown
as later text or as the answer. Nothing in the app calls it yet.

`attempt.mjs`'s `mark()` now stores a marked written answer as the app does
(`kind: "llm"` with the finalized review as `fb`; points where the app keeps
them), so a page can review the feedback. Every earlier page regenerates
byte-identically.

## For decision

1. **The answer box.** The frozen marked short-answer state is a disabled
   textarea; Review keeps it. A plain read-only text block would read less like
   a form. Recommended: keep the frozen box for now, since changing it changes
   the sitting too.
2. **The extended response collapsed.** The frozen state collapses *Your
   submitted response* so the mark sits high; Review keeps that. Recommended:
   keep.
3. **The sitting's *Your earlier version* note** (`.tm-earlier`) has a dashed
   edge. Under decision 25 dashed means not answered, so it should become a
   solid neutral edge when Results and Review are built.
