## The two things the page has to make obvious

1. **The subject and course, as Marginal resolved them.** *Business Studies ·
   Stage 6*, large, in its own panel.
   - The tick means exactly what `resolveAuthority` established: the file's
     subject key matched a registered package with marking criteria.
   - The stage and state are the file's claims and say so (*Stage 6, NSW, as
     stated in the file*). The package's own stage reads *Year 12*, so the page
     does not present *Stage 6* as resolved.
   - The panel is ticked only when the file can be added. On a stop verdict it
     shows what the file names, unticked. A green tick under *cannot be used*
     would contradict the verdict.
2. **Whether it is ready.** The verdict comes first, in one of the five group
   names, with a tone, a glyph and a sentence of its own. Nothing depends on
   colour alone.

## How a file is read, and where each step can stop

1. **JSON.** If it does not parse, the verdict is *Invalid file* and nothing
   else is shown. The parser's message goes in the details.
2. **Family.** A flashcard set is not an old or broken paper. It is sent to
   Create, where sets are imported.
3. **Version.** A version this release does not run is *Unsupported*, and
   nothing else in it is read. The contract does not guess what a different
   version means, so the page shows no subject and no contents from it.
4. **`examine()` with the registered packages.** The verdict is the worst state
   present. Given the packages, `examine()` also asks whether every question
   has a way to be marked (UX-TEST-23, fixed). An unregistered subject blocks
   only when some question needs that subject's marker.
5. **The library,** matched by `exam.id`, never the title, then by
   `exam.version`: new, the same, newer, older, or not comparable.

## Words, not diagnostics

- **A sentence for every code.** Every code the validator can emit has one,
  written for a teacher. The build fails if a code is added to the contract
  without one, so no finding can reach the page as a contract diagnostic.
- **Where, in the paper's own numbering.** *Section II* or *Question 11(b)*.
  When one sentence applies to several questions it is said once:
  *Questions 11(d), 12(c), 13, 15 and 16*.
- **Who can act.** Stop verdicts that the file's author can fix say *Whoever
  made the file needs to…*. The unregistered subject says the opposite:
  changing the file only helps if it names the wrong subject.
- **Disputed totals are not quoted as fact.** On the invalid page, Section II
  reads *marks disputed* and the paper's total reads *total marks disputed*,
  because the contract uses neither number.
- **Optional notes wait.** Under a stop verdict only what stops the file is
  listed. Optional notes are counted (*2 optional notes will be listed once the
  file can be added*), not hidden.
- **The contract stays on the page.** Its own sentence, code and path are
  under *Details for whoever made this file*, collapsed.

## Where each action goes, and what is stored

**Nothing is stored until Add to library.** Choosing another file, going back
to Test mode, or leaving the page discards the check.

| action | goes to |
| --- | --- |
| Add to library | Page 1, with the new paper's card first, in the Not started state |
| Choose a different file (bar or button) | the file chooser. The current check is discarded when a new file is read |
| Paste JSON instead, then Check this JSON | the same check. The result bar reads *Pasted JSON* in place of a file name, with *Edit pasted JSON*, which reopens the text as it was. Described here, not drawn |
| Open it in your library (already there) | Page 1, scrolled to that paper's card |
| Go to Create (a flashcard set) | Create, where set import stays |
| ← Test mode | Page 1 |

**Focus.** When a check finishes, focus moves to the verdict heading, so the
verdict is read the moment it exists. There is no live region.

## Decided (decision 21)

1. **A newer version replaces the paper in the library, and attempts stay
   pinned.** The verdict says so, where focus lands: *A newer version will
   replace the paper in your library. Existing attempts will continue using
   the version they started with.* The button reads *Replace with this
   version*, and the paper panel reads *Version 2 · replaces version 1 in your
   library*.
   - Two consequences of the rule are drawn so they can be overruled:
     - a version that cannot be ordered against the library's replaces, and
       says Marginal cannot tell which is newer;
     - an older version adds nothing.
   - How attempts are pinned is in `docs/testmode-attempt-state.md`.
2. **An unregistered subject is allowed when every question is locally
   markable.** That means multiple choice, a calculation with a complete answer
   and tolerance, or a closed short answer that declares phrase matching
   (decision 27; phrasings alone no longer make a question locally markable).
   - Such a paper is *Ready with limited support*, and says Marginal does not
     have written-response marking for the subject. The subject panel is
     neutral, neither ticked nor red: *Named by the file. Marginal has no
     marking for this subject, and this paper does not need it*.
   - If any question needs subject-aware marking, the paper *Needs something
     resolved*, and the page says how many.
3. **The five states** are *Ready to import*, *Ready with limited support*,
   *Needs something resolved*, *Unsupported* and *Invalid file*.
